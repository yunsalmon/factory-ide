# Languages and message contract

The language selector offers Korean, English and Japanese. A stored explicit choice wins over the browser's primary language; unsupported browser languages use English. Locale affects document language, accessible names, forms, help, diagnostics, event reasons, comparison and result views, and CSV headers. Numbers shown in metrics and result cells use `Intl.NumberFormat`; simulation times remain minutes. CSV numeric fields retain ungrouped decimal numbers for spreadsheet interoperability.

`web/locales.json` is the shared catalogue. The server supplies it locally as `/locales.js`; no translation service or CDN is used. `tr(key, args)` uses English when a locale entry is missing and a readable English message for unknown keys. UI keys are explicit, including literal segments in templates. Raw model names, machine/lot IDs, Python source, console output, traceback contents and custom decision reasons are not translated.

Built-in Python messages use the string subclass `messages.Message`. Existing callers still receive strings. Events retain `reason` and add `reason_message: {code, args}` only for built-in messages; checks use the same fields. Validation exceptions retain their historical string and attach structured details to API `error_message`. Results and parse responses add `warning_messages` parallel to `warnings`. Arguments may contain nested message descriptors. Plain strings returned from a user's `choose_candidate` remain untouched, even when they equal a built-in Korean explanation. The bundled example explicitly returns a built-in message; existing project functions need no changes.

Language changes re-render views without parsing or rewriting source. An open property form retains unsubmitted values. The browser saves the explicit locale separately from source and replay data. Matching source/result/cursor data are restored after refresh without executing Python again. Browser storage quotas can prevent saving unusually large traces; Python source saving remains independent. Trace JSON exports remain lossless and locale-independent.

Validation: `python -m unittest discover -s tests -v` and `python tests/browser_i18n.py` (optional Playwright/Chromium dependency). Existing Korean workflow tests explicitly use `ko-KR`; the i18n suite independently covers all three locales, live switching, refresh, translated built-in reasons, unchanged custom reasons, diagnostics, CSV and Python downloads.
